## P1.7 SSD/spindown resume test

**NOT RUN.** Required procedure:

1. Confirm `Debug → Disk Info` reports `SSD detected: yes`.
2. Set `Storage mode: SSD` and `Disk spindown` to 0, 7, 15 and 30 seconds.
3. At each setting, run 100 sleep/wake cycles; after each cycle play 10
   seconds, browse one directory and save one setting.
4. Stop at the first resume failure; record adapter/card/firmware.
5. Do not change the release default from 0 without a multi-device matrix.

## 2. Device baseline procedure

Record, with the same card and battery state:

- 5 cold boots and 5 warm reboots, small and large library;
- time to first UI frame and time to overlay READY;
- HFS+ read/write/flush counters and index-cache HIT/MISS immediately after
  mount;
- create 1/10/64/256 files; append 1 MiB; close; rename; delete; settings save;
- 30-minute idle/playback current runs with the screen off and on;
- storage wake graph (`PRE_WAKE`, `SLEEP`, `SLEEPNOW`, power-up/down, deep
  sleep) and PMU/I2C counts. Per-operation adapter call/flush counters are
  exposed now; ATA/PMU wake counters still need to be recorded on hardware.

## 3. Unverified high-risk areas

- zero-spindown idle-notify coupling and wake amplification;
- SSD explicit sleep/deep-sleep and adapter resume;
- album-art cache invalidation after overlay/file changes;
- runtime DB filename lookup and tagcache browser cursor changes;
- read-only stream read-ahead and cache coherence;
- path lookup/path-cache changes;
- ATA flush error propagation;
- bootloader minimal-state image and DFU recovery.

## 4. Acceptance before a non-beta release

- P0 power-loss matrix on hardware.
- Native HFS+ integrity and `diskutil verifyVolume` clean.
- 100-cycle SSD/spindown resume test.
- Host suite and ASan/UBSan.
- Firmware and bootloader build; `_moveend` inside `MOVE_AREA`.
- Recorded device boot, playback, settings persistence and overlay READY.
